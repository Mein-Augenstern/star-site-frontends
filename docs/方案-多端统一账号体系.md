# 技术方案：多端统一账号体系（微信登录 + 多身份绑定）

- 版本：v1.0（2026-10-10）
- 背景：小程序端只有用户名密码登录（member 表 username/password 均 NOT NULL，
  微信用户无法建号）；即将支持多端来源（微信小程序 / 支付宝小程序 / 独立 App / PC）。
- 原则：**经典账号-身份分离模型**（Devise multi-auth / 账号中心联邦登录同构），
  一次升级，所有端的登录方式都是"加一行 identity"，不再动账号主表。

## 1. 核心模型：member（账号）+ member_identity（身份）

```
member（账号主表：业务身份的唯一载体）
  id, nickname, avatar, gender, bio, status, deleted...
  phone（冗余，便于业务查询，权威在 identity）
  email（冗余同上）

member_identity（登录身份表：一个账号 N 条登录方式）
  id
  member_id        → member.id
  identity_type    WECHAT_MP | WECHAT_H5 | WECHAT_APP | ALIPAY_MP | PASSWORD | PHONE | EMAIL
  identifier       unionid/openid（微信系）/ 用户名 / 手机号 / 邮箱
  credential       bcrypt 密码（PASSWORD 用）/ session_key（微信系，可空）/ 空
  unionid          微信系专用冗余列（跨端归一键，可空）
  created_at / updated_at
  UNIQUE(identity_type, identifier)
```

要点：

- **多端归一的两把钥匙**：① 微信系各端（小程序/公众号/App/PC扫码）openid 各不同，
  但同主体 **unionid 相同** → 登录时按 unionid 找人，找不到再按 openid；
  ② 支付宝系同理有 user_id。不同生态之间靠**绑定同一 phone/email** 归一（后期）。
- member 表去掉 NOT NULL 约束（username/password 改可空，迁移存量数据）。
- 每种登录方式 = identity 表一行。"我的-账号与安全"页 = identity 列表页，
  绑定/解绑 = 增删行，天然支持。

## 2. 各端登录流程（经典时序）

### 2.1 微信小程序（本次落地）

1. `wx.login()` 静默取 code（无需用户授权）
2. 后端 `POST /api/auth/wx-login {code}` → 调微信 `jscode2session`（appid+secret）→ 得 openid+unionid+session_key
3. 按 unionid → openid 查 identity：
   - 命中 → 签发 JWT（静默登录，用户无感）
   - 未命中 → **静默注册**：建 member（昵称暂用"微信用户xxx"）+ identity 行 → 签发 JWT
4. 首次进入"我的"页引导点击完善昵称头像（`wx.getUserProfile`，需用户主动点，微信新规）

> 为什么静默注册：wx.login 不需要任何用户授权，微信生态的经典做法是"登录即有号"，
> 资料后补。这也是你说的"经典小程序"的体验。

### 2.2 支付宝小程序（预留，同构）

`my.getAuthCode()` → 后端换 user_id → identity_type=ALIPAY_MP，流程完全同构。
网关/接口/JWT 全部复用，只多一个阿里 SDK client。

### 2.3 PC 端（预留）

- 用户名密码（现有 PASSWORD identity 直接复用）
- 微信扫码 = 微信开放平台 website 应用 → unionid 归一（同一微信身份跨端）

### 2.4 独立 App（预留）

微信 App 登录（开放平台移动应用，unionid 归一）+ 手机号验证码登录。

## 3. 手机号/邮箱绑定（选填，"我的"页二次绑定）

| 通道 | 前提 | 方案 |
|---|---|---|
| 微信手机号快速填单 | **企业认证小程序** | `getPhoneNumber` → 后端解密/新接口 getPhoneNumber → 写 PHONE identity |
| 短信验证码 | 短信服务商（阿里云/腾讯云，需模板审核） | P1 接入；接口先按验证码模式设计，mock 通道开发 |
| 邮箱验证码 | **已有**（reminder 服务 EmailChannel SMTP 现成） | 发 6 位验证码（5 分钟有效，Redis 计数防刷）→ 校验后写 EMAIL identity |

- 手机号/邮箱**选填**，不阻塞任何功能；绑定后成为跨端归一钥匙 + 通知触达通道。
- 一个 phone/email 全局唯一（UNIQUE 约束在 identity 上，绑定前查重）。

## 4. 接口契约（网关 /api/auth，除绑定类均免 JWT）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /auth/wx-login | {code, anonymousId?} → LoginVO（静默注册/登录） |
| POST | /auth/login | 现有账号密码（走 PASSWORD identity 校验） |
| POST | /auth/register | 现有注册（建 PASSWORD identity） |
| POST | /auth/bind/email-code | 发邮箱验证码（JWT） |
| POST | /auth/bind/email | {code} 绑定（JWT） |
| POST | /auth/bind/phone | {phone, smsCode}（JWT，短信 P1 接入） |
| GET | /auth/identities | 我的登录方式列表（JWT） |
| DELETE | /auth/identities/{id} | 解绑（至少保留一种可登录方式） |
| POST | /auth/profile | 完善昵称/头像（JWT） |

JWT 不变（HS256，claims 现有 member_id 直接兼容所有业务服务——**下游零改动**）。

## 5. 存量迁移与兼容

1. DDL：新增 member_identity；member.username/password 改 NULL 允许
2. 迁移脚本：为每个存量 member 插一行 `PASSWORD identity(identifier=username, credential=现password)`
3. 现有 login/register 逻辑改为走 identity 表（对外行为不变，老账号无感）
4. 小程序登录页改版：主按钮"微信一键登录"（wx.login 静默），次入口"账号密码登录"
5. 网关：/api/auth/** 全部在免 token 白名单（已是），绑定类接口由服务自行校验 JWT

## 6. 开发态与外部依赖

| 依赖 | 状态 | 处理 |
|---|---|---|
| 微信 AppSecret | 需要你在微信公众平台拿（当前 AppID wx8bb4b89c...） | compose 加 WX_MP_SECRET；**开发态提供 mock 通道**：配置 `wx.mock-code-map` 时 code 直接映射 openid，不依赖真 secret，模拟器即可全链路跑通 |
| 短信服务商 | 未接 | P1：先上接口+mock 通道（验证码打日志），拿到服务商后换实现 |
| SMTP 邮箱 | ✅ reminder 已配 | 直接复用发验证码 |

## 7. 里程碑

- **M1（本次实现）**：member_identity 表 + 迁移 + /auth/wx-login（含 mock 通道）+ 小程序微信一键登录 + 邮箱验证码绑定 + 我的-账号与安全页
- M2：手机号绑定（getPhoneNumber / 短信）、支付宝小程序登录
- M3：PC 扫码、App 登录、unionid 跨端归一实战

## 8. 风险与对策

- session_key 属敏感信息：只存 identity.credential 供后期解密手机号用，永不下发客户端
- 静默注册的垃圾号：member.status 有禁用位；后续可加"未绑定任何联系方式 90 天回收"策略
- 解绑保护：解绑前校验"至少保留一种 identity"，防自锁
- 微信登录接口防刷：同 IP 频控（简单 Redis 计数，M1 先不做，P1 补）
