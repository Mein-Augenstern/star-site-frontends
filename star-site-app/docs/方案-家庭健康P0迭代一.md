## 2. 数据模型

新表 `visit_record`（docker/mysql-init/14-visit.sql，同时手工应用到运行库）：

```sql
CREATE TABLE IF NOT EXISTS `visit_record` (
  `id`                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `family_member_id`  BIGINT UNSIGNED NOT NULL COMMENT '家庭成员id',
  `visit_date`        DATE     NOT NULL COMMENT '就诊日期',
  `hospital`          VARCHAR(128) NOT NULL COMMENT '医院',
  `department`        VARCHAR(64)  DEFAULT '' COMMENT '科室',
  `diagnosis`         VARCHAR(255) DEFAULT '' COMMENT '诊断',
  `medication`        VARCHAR(500) DEFAULT '' COMMENT '用药/处方摘要',
  `cost`              DECIMAL(12,2) DEFAULT NULL COMMENT '费用(元)',
  `remark`            VARCHAR(255) DEFAULT '',
  `deleted`           TINYINT NOT NULL DEFAULT 0,
  `created_at`        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_member_date` (`family_member_id`, `visit_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='就医记录';
```

不动的表：health_report / health_indicator / reminder_*（提醒规则改造留待迭代二，
届时 ALTER reminder_rule 加 family_member_id 并评估扫描兼容，见 PRD #8）。

## 3. 接口契约（网关 /api 前缀）

| 方法 | 路径 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| GET | /health/visits | familyMemberId?、page、size | PageVO&lt;VisitVO&gt; | 按就诊日期倒序；不传成员=全家（归属收口） |
| POST | /health/visits | VisitCreateDTO | VisitVO | 必填：familyMemberId、visitDate、hospital |
| DELETE | /health/visits/{id} | — | void | 逻辑删除，先校验归属 |

VisitCreateDTO 字段与表一一对应；VisitVO 增加 id/createdAt。
校验：@NotNull familyMemberId/visitDate/hospital；hospital 长度 ≤128。
